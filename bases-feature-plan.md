# Bases Feature — Plan

## Решено (от заданието)
- Нов таб **„Бази"** → общо 4 таба, подредени **2 реда × 2 таба** (`.tab-nav` с flex-wrap, `.tab-btn` flex-basis 50%); пак responsive.
- Списък с бази: редове с 2 колони — **име** и **локация**; редовете се колапсват като другите таблици в апа (accordion стил като куестовете: точно един expanded, клик на бутон/drag-handle не toggle-ва).
- Всеки ред: бутон **детайли** (📖) и бутон **триене** (🗑, с confirm).
- „Детайли" рутира до отделна „страница" за базата (hash routing `#base/<id>`):
  - редактируеми **име** и **локация**
  - поле **история** (свободен текст — история на населеното място)
  - табовете отгоре се скриват; има бутон **„← Назад"** връщащ към списъка с бази (табовете отгоре).
- В детайлната страница — 3 таблици с добавяне (pattern от апа: „+ Добави" бутон + modal за add/edit):
  1. **Сгради и съоръжения** (buildings)
  2. **Население** (populace)
  3. **Продукция** (production)
- TDD, модулен код (нов `modules/bases.js`), Vitest unit + Playwright e2e както останалите фичи.

## Отговори от брейнсторма
1. **Полета на трите таблици**: свободен текст засега — ползват го само играчът и ДМ-ът, без структурирани типове/числа. Дизайн: всеки ред = **име + свободен текст детайли** (2 колони, колапсващи като другите таблици).
2. **Сортировка**: при edit на база тя отива най-отгоре в таблицата — същият pattern като другите таблици в shared inventory (splice+unshift, recently-edited-first). Важи и за трите под-таблици в детайлната страница. Drag & drop със SortableJS също, като другите таблици.
3. **Без снимки/карти към база** — картите са си в Maps таба; пазим Firebase free tier, фийчърът не се ползва активно (само играч + ДМ).

## Данни (решено)
Колекция `bases`, **ЕДИН документ** `bases/index`:
```
{ list: [ { id, name, location, history,
            buildings:  [ { name, details } ],
            populace:   [ { name, details } ],
            production: [ { name, details } ] } ] }
```
- Същият `{list}` патърн като ITEMS_DOC/QUESTS_DOC/maps-индекса; редът в `list` = ред на показване.
- `id = crypto.randomUUID()` — стабилна котва за routing-а (`#base/<id>`), не се чупи от преподредба.
- **Един док, не по док на база** (промяна спрямо първоначалната ми скица): всичко е чист текст, 1MiB/док лимитът е далеч, а един док = **1 read на snapshot** — пази free tier-а (изрично изискване). Снимки няма (реш. 3), така че причината за отделните докове при maps тук не съществува.
- `BASES_DOC = doc(db, 'bases', 'index')` в `modules/firebase.js`.

## Routing (решено)
- Hash-базиран: `#base/<id>` = детайлен изглед; празно/друго = табов изглед. Работи на GitHub Pages, пази browser/телефонния back бутон.
- При отворен детайл: `.tab-nav` и `.tab` дивовете скрити, `#baseDetail` видим. „← Назад" → `location.hash = ''` → табовете, активен таб „Бази".
- Непознат/изтрит id в hash-а → обратно към списъка.
- Deep link при зареждане: route-ът се преоценява и след пристигане на bases snapshot-а (данните може да дойдат след DOMContentLoaded).

## Извън обхват
- Export/Import bundle-ът (v1) не се пипа — базите не влизат в него (както и картите).
- Security rules за колекция `bases` — ръчна стъпка на собственика във Firebase конзолата, не на агент.
- sw.js не се пипа (network-first покрива новите модули).
